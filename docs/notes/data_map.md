# Data map of the driver image (bin/manatee_arm.bin, 0x0000-0x82FF)

Every non-instruction range of the image (from `tools/gaps.py`, plus the < 16-byte items that
matter). Names are the Ghidra labels (tools/ghidra/annotations/40_fx_data.json unless noted); tables
needed by C are in src/arm/tables.c (generated by `tools/gen_tables.py`, declared in manatee.h).
Confidence: H = users and meaning verified in the code, M = users known, meaning inferred,
L = guess.

General patterns:
- Code is followed by `00 00 A0 E1` (= `mov r0,r0`, a NOP) as alignment padding before most literal
  pools (e.g. 0x318, 0x368, 0x8EC, 0x14A8, 0x51E4, 0x5D94, 0x5DEC, 0x6168, 0x62DC, 0x6AC4, 0x6C30,
  0x6DB0); the rest of each small gap is an ordinary PC-relative literal pool (addresses, masks,
  magic words) of the function just before it. Pools that contain only literals are not listed
  individually below unless they hold something notable.
- Scratch variables of several routines live inside the image (the code is in RAM).
